# Releasing xbridge

1. Bump the version in `Sources/xbridge/main.swift` before building.
2. Run `swift test` and `swift build -c release`. Check `xbridge --version`, the read-only `xbridge status --fix` native permission-status path (Xcode 27+), and that a source install's `xbridge skill` output exactly matches `skills/xbridge/SKILL.md`. Approval must remain a human-run sudo command, not an automated check.
3. Commit and push the source changes, then tag that commit `vX.Y.Z` and push the tag.
4. The `Release` GitHub Actions workflow builds and Developer ID-signs both binaries before packaging, publishes the archive to the GitHub release, and updates `4rays/homebrew-tap/Formula/xbridge.rb`. Wait for the workflow and verify the release asset and formula before reporting success. The workflow needs `HOMEBREW_TAP_TOKEN` with write access to the tap, `MACOS_SIGNING_CERTIFICATE_P12_BASE64` containing the base64-encoded signing identity export (certificate and private key), and `MACOS_SIGNING_CERTIFICATE_PASSWORD` containing its export password. The identity is `Developer ID Application: Four Rays AB (RGS98ZRDY6)`. It is imported into a temporary runner keychain that is deleted after packaging, including on failure. Never commit the export or its password.
5. If the tap update fails, download the **published artifact**, calculate its SHA-256, update the formula's URL and hash, remove any `bin.install "xbridge-allow"` line, and ensure `pkgshare.install "xbridge-skill.md"` is present, then validate and push the tap change. Never calculate a checksum from a separate local build: archive bytes can differ.

The archive has one top-level `xbridge-bin/` containing `xbridge`, `xbridged`, and `xbridge-skill.md` copied from `skills/xbridge/SKILL.md`. Homebrew installs the Markdown into `share/xbridge/`; `make install` follows the same layout. The Accessibility helper is no longer shipped.

Keep the signing identifiers `net.4rays.xbridge` and `net.4rays.xbridged` stable across releases. Xcode's durable signed-agent grants match the Team ID and signing identifier, so a new binary hash or installation path does not require another agent approval when the signing identity is preserved. The first signed production daemon still needs its own approval; the experiment's probe grant does not cover it. Plain `swift build` and `make install` do not apply Developer ID signing. This workflow signs but does not notarize the release.

After installing a published release, check `codesign -dv --verbose=4 "$(brew --prefix xbridge)/bin/xbridged"` for `TeamIdentifier=RGS98ZRDY6` and `Identifier=net.4rays.xbridged`, and run `codesign --verify --strict "$(brew --prefix xbridge)/bin/xbridged"`. Confirm native Xcode status identifies the daemon as signed before approving it with `--always`.
